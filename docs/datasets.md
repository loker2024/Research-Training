# 时间序列预测常用数据集介绍

本文档面向刚开始做长时序预测实验的同学，介绍本课题计划使用的 ECL、ETT、ILI 和 Traffic 数据集。重点不是背数据集名称，而是理解它们分别代表什么预测场景、适合验证模型的哪些能力，以及放到代码里时需要注意什么。

## 1. 先理解时间序列数据集

时间序列数据一般按时间顺序排列，每一行代表一个时间点，每一列代表一个观测变量。

典型表格形态如下：

| 时间 | 目标变量 | 外生变量 1 | 外生变量 2 |
| --- | ---: | ---: | ---: |
| 2024-01-01 00:00 | 12.3 | 4.8 | 0 |
| 2024-01-01 01:00 | 12.9 | 5.1 | 1 |
| 2024-01-01 02:00 | 13.5 | 5.0 | 2 |

在预测任务中，模型会读取一段历史窗口，例如过去 96 个时间点，然后预测未来 24、48、96 或更长时间点。

本课题中有两个常见设置：

- 单变量预测：只使用目标变量的历史值预测目标变量未来值。
- 多变量预测：同时使用目标变量和多个相关变量的历史值，预测未来目标或未来所有变量。

## 2. ETT 数据集

ETT 是 Electricity Transformer Temperature 的缩写，中文可理解为“电力变压器温度数据集”。它记录电力系统中变压器相关的负载、油温等时间序列。

常见版本：

| 数据集 | 粒度 | 说明 |
| --- | --- | --- |
| ETTh1 | 小时级 | 较长时间跨度的小时数据 |
| ETTh2 | 小时级 | 另一组小时级变压器数据 |
| ETTm1 | 分钟级 | 更细粒度的 15 分钟数据 |
| ETTm2 | 分钟级 | 另一组分钟级变压器数据 |

常见字段包括：

- `date`：时间戳。
- `OT`：Oil Temperature，通常作为目标变量。
- 其他负载或电力相关变量：可作为外生变量或多变量输入。

适合用于：

- 快速验证模型流程是否正确。
- 比较 LSTM 与 Transformer 的基本性能。
- 做不同预测步长对比，例如 24、48、96、168、336。

注意事项：

- ETT 数据规模适中，适合作为第一批实验数据。
- 如果刚开始做课题，建议优先使用 ETTh1 或 ETTm1。
- `OT` 常被设为目标列，对应 notebook 中的 `TARGET_COL`。

## 3. ECL 数据集

ECL 是 Electricity Consuming Load 的缩写，通常指多个用户或区域的用电量数据。它是多变量长时序预测中非常常用的数据集。

数据特点：

- 变量数量较多。
- 周期性明显，例如日周期、周周期。
- 比 ETT 更能考验模型处理多变量依赖的能力。

适合用于：

- 多变量预测实验。
- 验证 Transformer、PatchTST 这类模型是否能利用多个变量之间的关系。
- 分析季节波动性，例如每天和每周用电规律。

注意事项：

- 变量多会增加模型输入维度和计算量。
- 初次实验可以先只取部分列，确认流程跑通后再使用全部变量。
- 用电数据中可能存在不同用户量级差异，因此标准化非常重要。

## 4. ILI 数据集

ILI 是 Influenza-Like Illness 的缩写，中文可理解为“类流感病例比例数据集”。它通常来自公共卫生统计，用于预测流感相关趋势。

数据特点：

- 时间粒度通常是周级。
- 数据长度相对较短。
- 季节性非常明显，常在冬季出现高峰。

适合用于：

- 观察模型在小样本、强季节性数据上的表现。
- 分析长期预测中的趋势偏移。
- 讨论公共卫生预测场景下的误差风险。

注意事项：

- 因为数据较短，不适合盲目使用很长的 `seq_len`。
- 训练集、验证集、测试集切分后，每部分样本可能很少。
- MAPE 对接近 0 的病例比例比较敏感，报告中需要解释这一点。

## 5. Traffic 数据集

Traffic 数据集通常记录多个道路传感器或路段的交通流量、占有率等信息。

数据特点：

- 变量数量多。
- 时间规律明显，例如早晚高峰、工作日与周末差异。
- 多变量之间可能存在空间相关性，例如相邻路段流量会互相影响。

适合用于：

- 检验模型处理高维多变量时间序列的能力。
- 分析长预测步长下误差累积问题。
- 讨论计算复杂度，因为 Traffic 往往比 ETT 更重。

注意事项：

- 数据维度高时，LSTM 训练可能较慢，Transformer 显存消耗也会上升。
- 如果本机配置有限，建议先降低 batch size 或只选部分变量。
- 交通数据的异常值和节假日效应可能影响预测结果。

## 6. 初学者该先选哪个数据集

建议顺序如下：

| 阶段 | 推荐数据集 | 原因 |
| --- | --- | --- |
| 第一步 | ETTh1 | 数据规模适中，字段较清晰，适合跑通流程 |
| 第二步 | ETTm1 | 时间粒度更细，适合观察长输入窗口效果 |
| 第三步 | ECL | 多变量较多，适合验证 PatchTST 类模型优势 |
| 第四步 | ILI | 强季节性、小样本，适合写分析讨论 |
| 第五步 | Traffic | 维度高、计算更重，适合作为进阶实验 |

如果只是完成第一版代码验证，优先选择 ETTh1。等 notebook、指标和图都能正常生成后，再扩展到 ECL、ILI 和 Traffic。

## 7. 数据如何放入本项目

把下载好的 CSV 文件放入 `data/` 目录，例如：

```text
data/
├── ETTh1.csv
├── ETTm1.csv
└── electricity.csv
```

然后在 notebook 的配置单元中修改：

```python
cfg = ExperimentConfig(
    data_path="../data/ETTh1.csv",
    time_col="date",
    target_col="OT",
    use_synthetic_demo=False,
)
```

如果 CSV 的时间列或目标列名称不同，只需要对应修改 `time_col` 和 `target_col`。

## 8. 数据切分为什么不能随机

普通机器学习任务中经常随机划分训练集和测试集，但时间序列预测不能这样做。原因是随机划分会把未来数据混入训练集，使模型提前看到未来分布，导致结果虚高。

正确做法是按时间顺序划分：

```text
过去数据                  未来数据
|-------- train --------|--- val ---|--- test ---|
```

本项目 notebook 已经按这个原则实现。

## 9. 选择预测步长

预测步长 `pred_len` 表示要预测未来多少个时间点。不同数据粒度下，它对应的真实时间长度不同。

以小时级数据为例：

| `pred_len` | 含义 |
| ---: | --- |
| 24 | 预测未来 1 天 |
| 48 | 预测未来 2 天 |
| 96 | 预测未来 4 天 |
| 168 | 预测未来 1 周 |
| 336 | 预测未来 2 周 |

以 15 分钟级数据为例：

| `pred_len` | 含义 |
| ---: | --- |
| 96 | 预测未来 1 天 |
| 192 | 预测未来 2 天 |
| 336 | 预测未来 3.5 天 |
| 720 | 预测未来 7.5 天 |

写报告时需要说明数据粒度，否则单独写 `pred_len=96` 不够清楚。

## 10. 和本课题模型的关系

不同数据集可以帮助观察不同模型特点：

| 模型 | 更适合观察的问题 |
| --- | --- |
| LSTM | RNN 基线效果、长期依赖衰减、误差累积 |
| Transformer | 自注意力建模长距离依赖的能力，以及计算复杂度 |
| Informer | 长序列输入下稀疏注意力是否降低计算成本 |
| Autoformer | 趋势与季节分解是否提升长期预测稳定性 |
| PatchTST | patch 化后是否更适合长输入、多变量预测 |

第一版 notebook 已经提供 LSTM、Transformer 和 PatchTST-lite。后续扩展 Informer 和 Autoformer 时，建议优先在 ETTh1 上验证正确性，再迁移到 ECL 和 Traffic。
